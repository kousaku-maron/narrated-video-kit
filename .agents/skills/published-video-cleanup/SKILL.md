# 公開済み動画の整理

このリポジトリでは公開後の再制作を前提にしない。動画ファイルは全削除し、企画・台本・構成・出典・投稿情報を制作記録として残す。ネットにない本人録画なども、復元用コピーや切り出しを作らず削除する。

## 対象と実行依頼

- リポジトリの `AGENTS.md`、`projects/README.md` と対象の `VIDEO.md`、`SCRIPT.md`、`assets/SOURCES.md`、`project.json`、必要な `notes/`・`publish/PUBLISH.md` を読む。
- 「公開済みの○○を整理して」など、対象を指定した整理依頼は、この方針で動画を削除する許可として扱う。既に対象と実行意思が明確なら、追加の承認やバックアップを要求しない。相談・容量確認・スキル作成の依頼だけでは削除しない。
- 対象が不明ならユーザーに確認する。書き出し済みであることや「公開した」という申告だけで、YouTube上の動画の存在確認を省略しない。
- `00000000-demo` は対象外。一括依頼でもプロジェクトごとに記録・実行する。対象外のプロジェクト、共通 `assets/`、`pelsona/`、別の場所の元ファイルは整理しない。

## 削除前に残す記録

1. `VIDEO.md` にYouTubeの公開URLと、分かる場合は公開日を記録する。ユーザーが今回提供したリンクを優先する。既存の記録から取得できる場合は利用し、不明なら「この動画を公開したYouTubeのリンクを教えてください」と求める。リンクを推測しない。リンクを書くだけでは削除条件を満たさず、次の存在確認を必須とする。
2. `assets/SOURCES.md` に各動画素材のファイル名・分かる素材ID・元URLを残す。`.source.txt`、企画、メモから補完し、ページURLやSteam movie IDしか分からない場合もその情報を保持する。同じ素材のコピーはまとめてよい。ネットにない素材は「本人録画／ユーザー提供など、ネット公開なし。削除後は復元不可」と記録する。不明な出典は「出典不明」と記録し、URLを捏造しない。
3. `project.json` は当時の構成記録としてそのまま残す。動画参照の削除や尺の変更をしない。素材削除後に `npm run check/studio/render/final` を実行しない。参照切れはこの整理方針の結果として扱う。

## YouTube上の対象動画を確認する

- 削除対象の計画を作った後、削除前にYouTubeのリンクを実際に開く。まずWebツールで直接ページを読み、動画の情報が取得できなければ利用できるブラウザツールで確認する。検索結果の抜粋、URLの書式、HTTP 200、過去の確認記録だけでは存在確認としない。
- YouTubeページまたはYouTube Studioで動画が存在し、再生可能または公開・限定公開であることを確認する。処理中・予約公開・非公開・削除済み・利用不可を公開済み扱いにしない。
- タイトル・チャンネルと、説明・サムネイル・映像・尺など確認できる情報を企画・投稿文・台本と照合し、対象プロジェクトの完成動画であることを確認する。素材のトレーラーや別の投稿を完成動画と取り違えない。タイトルが違うなど対応が不明な場合はユーザーに確認する。
- ページにアクセスできない、動画情報が不足している、ログイン等で確認ができない場合は削除しない。分からない点を説明し、正しいリンクや、アクセスできるブラウザ／YouTube Studioでの確認をユーザーに求める。待っている間は対象一覧・出典の整理まで進めてよい。「公開した」という申告だけで確認済みを作らない。
- 実際に確認できたら `notes/published-video-verification.json` に `project`、`youtube_url`、タイムゾーン付きISO日時の `checked_at`、確認した `title`・`channel`、確認手段の `method`、存在確認の `exists: true`、対応確認の `matches_project: true`、照合根拠の `evidence` を保存する。根拠はツールで観測した内容だけを書く。計画作成後の新しい確認を使い、過去の記録を今回の確認として使い回さない。

## 動画ファイルの整理

補助スクリプト [scripts/cleanup_videos.py](scripts/cleanup_videos.py) はPython標準ライブラリだけで動く。リポジトリのルートで実行する。

```sh
# 削除対象・容量の確認のみ。--plan-out を付けた場合だけ計画JSONを書く。
python3 .agents/skills/published-video-cleanup/scripts/cleanup_videos.py \
  --project YYYYMMDD-name --youtube-url '公開動画のURL' \
  --plan-out /tmp/YYYYMMDD-name-video-cleanup.json

# YouTube上の存在と対象の一致を確認し、確認記録を保存してから実行。
python3 .agents/skills/published-video-cleanup/scripts/cleanup_videos.py \
  --project YYYYMMDD-name --apply /tmp/YYYYMMDD-name-video-cleanup.json \
  --verification projects/YYYYMMDD-name/notes/published-video-verification.json
```

- 対象は `projects/<名前>/`、`remotion/out/<名前>/`、`remotion/public/projects/<名前>/` 内の動画だけ。`footage/`・`originals/`・`publish/`・`work/` 内も含む。試写用フォルダや描画用フォルダを丸ごと削除しない。
- 計画のファイル一覧と容量を確認する。スクリプトは一般的な動画拡張子と `project.json` の `kind: video` を使う。特殊な形式や別の保存場所が見つかったら個別に確認し、勝手に削除範囲を広げない。
- 画像、音声、字幕、サムネイル、HTML、台本、企画、JSON、メモ、出典のテキスト、制作スクリプトを残す。`originals/` 内の画像や音声も残す。Gitの追跡・除外設定はこの整理では変更しない。
- 計画から対象が増減・変更した場合は実行が止まる。再度一覧を作り、変更内容を確認する。シンボリックリンクの先は削除しない。
- スクリプト自体はYouTubeにアクセスしない。エージェントによる存在・対応確認と、その記録が必要。確認記録がない、別のプロジェクト／URLの記録、計画より古い記録では動画を削除できない。

## 完了記録と繰り返し実行

- スクリプトは削除前に `notes/video-cleanup-history.json` に実行対象・公開URL・存在確認の記録・日本時間の日時を保存し、実行後に削除結果を記録する。失敗・中断時は実際に削除済みのものだけを完了扱いにし、残りを報告する。
- 正常終了後、`VIDEO.md` の状態を「公開済み・動画ファイル削除済み」にし、整理日と履歴ファイルを追記する。現在の完成動画の所在はYouTubeのURLに更新し、過去の制作メモは残す。「再生成」の説明がある場合、動画素材を削除したためそのままでは実行できないことを添える。
- 再実行して対象動画がなければ「整理済み」と報告する。新たな動画があれば、新しい計画と履歴で整理する。既存の出典や履歴を消したり、同じ説明を重複追記しない。
- 最後に対象数・削除したファイル容量の合計・残した記録・公開URL・失敗があればその対象を簡潔に報告する。容量はファイルサイズ合計であり、実際のディスク空き容量の増加と同一とは限らない。
