# 動画テンプレート

`projects/` は各動画の実データ、`templates/` は次の動画へ持ち越す制作方針と文書のひな形を置く場所です。ゲーム固有の事実・台詞・素材・完成ファイルはテンプレートに入れません。

- [インディーゲーム体験レビュー](indie-game-review/README.md)：デモ版やPlaytestを実際に遊び、発売前のウィッシュリスト候補として紹介する動画。InvokyrとStink Buddiesで固まった構成に、Grr Grr Gnomesの制作で磨いたサムネイルと章トランジションを反映しています。作品固有の色と文言は毎回選び直します。
- [Steamセール向け複数作品紹介](steam-sale-picks/README.md)：セール前に次に遊ぶ候補を選ぶ動画、または開催中に割引が確認できた作品を紹介する動画。公式情報・公開映像を基に各作品の選びどころを語り、価格と割引の確認時点を明示します。実プレイは前提にしません。

テンプレートを使っても、映像を実際に描画する設定は各プロジェクトの `project.json` が基準です。共通の描画部品は `remotion/` に置き、文書のひな形と混ぜません。

## 映像素材の選び方

紹介・解説の背景は公式トレーラーを基本にし、本人の体験を示す場面では自分のプレイ映像も使います。了承済みのトレーラー採用方針への確認は繰り返しません。作品ごとの取得元・明示された利用条件・必須表記を `assets/SOURCES.md` に記録し、公式映像であることを一律の転載許諾とは扱いません。

公式トレーラーがない、利用が明示的に禁止されている、技術的に取得できないなどの理由で背景を静止画へ替える場合は、実装前に理由・対象章と時間帯・映像への影響・候補画像そのものを投稿者へ説明し、確認後に採用します。理由と確認結果は `notes/` に残します。サムネイルや企画で決めたタイトルカードの静止画は、背景映像の代替とは分けて扱います。

## 制作と公開

採用する型の `VISUALS.md`、`TRANSITIONS.md`（ある場合）、サムネイルHTMLまで確認して画面を組みます。レビュー型の白枠・番号付きの章タイトルは `chapterTransition`、セール型の作品切り替えは `overlays` の `transition` を使います。冒頭タイトル・章タイトル・サムネイルは役割が異なるため、企画に合うものを選びます。

[デザイン部品](visual-designs/README.md)には、既存のサムネイルの型と、告知・期間を大きく見せる別案をまとめています。採用版のサムネイル編集原稿は各プロジェクトの `publish/thumbnail.html` に置きます。

台本は日時・人数・数量・価格をアラビア数字で書き、字幕用 `text` とTTS用 `speechText` を分けます。読み辞書は [音声ツール](../speech/README.md) の共通処理へ渡し、語り手・作品ごとの読みを共通engineに埋め込みません。不要な注意事項の羅列やトレーラー宣言を必須にせず、締めは簡潔にします。冒頭と締めの入口にトランジションは置かず、本編作品間の演出を維持します。冒頭の尺は企画で決めます。

新規制作では [YouTube制作・公開チェック](YOUTUBE_CHECKLIST.md) を使い、冒頭30秒の約束と関連動画への導線を制作時に計画します。`project init` が `publish/YOUTUBE_CHECKLIST.md` を作るので、公開前・公開後の確認と次回に生かす分析をその文書へ記録します。既存動画へ一括適用しません。

投稿文は動画固有の2〜3行（誰向け・紹介内容・選定条件） → 必要なセール情報 → チャプター → 公式Steamストア → ハッシュタグ → 映像出典の順。音声・BGMの任意クレジットは加えず、素材の必須利用条件は保持します。[upload-record.json](upload-record.json) は公開記録の共通ひな形で、`project init` が新規プロジェクトへコピーします。ID・JST日時・設定・チェック結果は実際に確認してから記入します。主要語句1〜2個をタイトルと説明へ自然に使い、正式ゲーム名付きチャプターは `00:00` 開始・3区間以上・各10秒以上にします。ハッシュタグは関連する少数、通常タグは誤綴りなどの補助として分けます。
